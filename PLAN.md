про# План работ

## Железо и ограничения

CPU i9-13900H (20 потоков), 32 ГБ RAM, CUDA нет. Модели маленькие: GPT-2 на 2–4 слоя,
`n_embd` 64–128, контекст 50–100 событий. Тяжёлые прогоны — Kaggle/Colab GPU при необходимости.

## Датасет

Основной — **KuaiRec** (короткие видео Kuaishou). Есть `play_duration`, `video_duration`,
`watch_ratio`, время события; `big_matrix` (7176 пользователей × 10728 видео, ~12.5 млн
событий) для обучения и `small_matrix` (1411 × 3327, заполнена почти полностью). Вторая
матрица — «оракул»: для пары пользователь–видео известен реальный отклик, поэтому
reward hacking проверяется по истинному `watch_ratio`, а не только по reward model.

Запасные: KuaiRand-Pure (есть случайные показы `is_rand` для несмещённой оценки), Yambda
(музыка, `played_ratio`, лайки, organic-флаг — постановка статьи 2607.02818).

## Этапы

1. **Данные** (`src/rlrec/data.py`). Загрузка, фильтр по 5-core, перенумерация id,
   глобальное разбиение по времени: train < t1 ≤ val < t2 ≤ test. Признаки для reward:
   `watch_ratio` (клип в [0, 3]), длительность, факт возврата пользователя на следующий
   день, длина сессии (разрыв > 30 мин). Проверка утечек: в test нет событий раньше t2.
2. **Базовая модель** (`model.py`, `train_sft.py`). `GPT2LMHeadModel`, токены — id видео,
   next-item prediction, full softmax CE. Метрики Recall/NDCG/MAP@{10,20} на val/test,
   бейзлайны Popular и SASRec-подобный (тот же GPT-2) для калибровки.
3. **Reward model** (`train_rm.py`). Трансформер по истории + кандидат → `watch_ratio`
   (регрессия/BCE) и вероятность «досмотра» (`watch_ratio ≥ 1`). Качество: RMSE, AUC,
   корреляция по Спирмену на test; отдельно на `small_matrix` против истины. Проверка
   смещения RM по длительности видео и популярности.
4. **RL-дообучение** (`train_rl.py`). Начать с REINFORCE с baseline (RLOO/GRPO-стиль:
   K сэмплов на контекст, advantage относительно среднего) + KL к SFT-модели; затем PPO
   по схеме GPTRec (2403.04875) как вариант. Off-policy REINFORCE с importance weights
   из 2607.02818 — если останется время.
5. **Варианты вознаграждения**:
   - $r=\widehat{\text{watch ratio}}$ — ожидаем сдвиг к коротким видео;
   - время просмотра $\widehat{\text{ratio}}\cdot\text{duration}$ — сдвиг к длинным;
   - смесь с релевантностью: $r=\widehat{\text{ratio}}+\lambda\log\pi_{\text{SFT}}$;
   - штраф за повтор и популярность;
   - долгосрочный прокси: вероятность возврата / длина сессии (отдельная голова RM).
6. **Многошаговая генерация**. Rollout на 5 шагов с добавлением сгенерированного объекта
   в контекст; сравнить: (а) только объект, (б) объект + предсказанный отклик RM.
   Мерить дрейф: доля повторов, popularity, расстояние до реального продолжения, рост
   reward по шагам против истины на `small_matrix`.
7. **Анализ**. Фронт Парето NDCG@10 ↔ reward по сетке $\beta_{KL}$ и $\lambda$; coverage,
   Gini, доля уникальных топ-10 по пользователям, средняя длительность и популярность
   рекомендаций до/после RL; кейсы конкретных пользователей.
8. **Отчёт** `README.md`: постановка, разбиение, результаты, ограничения (офлайн против
   онлайн), воспроизведение (`scripts/*.ps1`, конфиги в `configs/`).
